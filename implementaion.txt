Implementation Plan — Final Version
What The System Does

User inputs a scenario in plain language. System retrieves relevant historical context from curated hosted pages via Tavily. LLM estimates ODE parameters from that context. ODE engine simulates health and energy trajectories forward. Results are plots and JSON outputs.

Ground truth validation runs separately on past known events to prove the system is accurate before trusting future predictions.

Tech Stack
Language:          Python 3.11+
ODE Solver:        Custom RK4 (NumPy)
LLM:               Claude API (claude-sonnet-4-6)
Web Retrieval:     Tavily API (1000 free calls/month)
Knowledge Graph:   NetworkX (local, saved as .gexf)
Data Processing:   pandas, numpy
Output:            matplotlib (plots), JSON, CSV
Hosting:           GitHub Pages (static HTML, free)
Config:            python-dotenv
Testing:           pytest
Version Control:   Git + GitHub

Knowledge Graph — What It Stores

Tavily handles text retrieval. The knowledge graph handles structured causal chains that don't exist anywhere on the web in queryable form.

NODES:
  Region        → "UK_Yorkshire", "UK_SouthEast"
  PowerPlant    → "Drax_Unit1", "Ratcliffe_on_Soar"
  PolicyEvent   → "UK_Coal_Phase_Out_Announcement_2015"
  EnergyEvent   → "Drax_Unit1_Closure_April_2023"
  PollutionEvent→ "PM25_Drop_Yorkshire_Oct_2023"
  HealthEvent   → "Respiratory_Admissions_Drop_Q1_2024"
  TimePeriod    → "2023_Q2", "2023_Q4"

EDGES:
  PolicyEvent  -[TRIGGERED]->   EnergyEvent
  EnergyEvent  -[PRECEDED]->    PollutionEvent   (lag: 6 months)
  PollutionEvent-[PRECEDED]->   HealthEvent      (lag: 3 months)
  Region       -[DOWNWIND_OF]-> Region           (Psi source)
  PowerPlant   -[LOCATED_IN]->  Region

This gives the LLM structured answers to questions like:
"What happened to health outcomes 9 months after a similar plant closure?"

The Complete Pipeline — Step By Step
Phase 1 — One Time Setup (you run these once)
STEP 1: Download raw data
  → National Grid ESO CSVs
  → NHS HES data
  → DEFRA air quality CSVs
  → Save to data/raw/

STEP 2: Run scripts/prepare_ground_truth.py
  → Cleans raw CSVs
  → Extracts observed X and H values per quarter
  → Saves to data/ground_truth/uk_coal_phaseout.json

STEP 3: Run scripts/build_knowledge_graph.py
  → Reads events_timeline.json
  → Builds NetworkX graph
  → Saves graph.gexf

STEP 4: Run scripts/build_hosted_pages.py
  → Converts raw data into readable HTML pages
  → Saves to hosted_data/

STEP 5: Push hosted_data/ to GitHub Pages
  → Tavily can now search these URLs
Phase 2 — Every Simulation Run
STEP 1: User inputs scenario
  "What happens if UK closes all remaining
   gas plants by 2027 in Yorkshire?"

STEP 2: rag/retriever.py runs
  → Tavily searches allowed URLs with scenario as query
  → Returns relevant content (energy data, health data,
    paper excerpts, policy context)
  → NetworkX graph queried for similar past events
    and their causal chains
  → Both results combined into context block

STEP 3: llm/estimator.py runs
  → Sends to Claude:
      - User scenario
      - Tavily retrieved content
      - Graph query results
      - Parameter schema
      - System prompt
  → Claude outputs 30 parameters as JSON

STEP 4: llm/validator.py runs
  → Checks all ranges valid
  → Clamps out-of-range values
  → Returns clean parameter dict

STEP 5: core/runner.py runs
  → Loads initial conditions
  → Passes parameters to ODE engine
  → RK4 integrates 18 coupled ODEs forward
  → Returns trajectory JSON

STEP 6: Outputs generated
  → outputs/trajectories/scenario_name.json
  → outputs/plots/trajectory_plot.png
  → outputs/plots/scenario_comparison.png
Phase 3 — Validation (runs separately)
STEP 1: validation/backtest.py runs on past event
  → Takes Drax closure 2023 as input
  → Runs full pipeline
  → Gets predicted trajectories

STEP 2: validation/metrics.py runs
  → Loads ground_truth/uk_coal_phaseout.json
  → Compares predicted vs actual
  → Calculates MSE and trajectory error

STEP 3: validation/weight_adjuster.py runs
  → If retrieval led to accurate prediction →
    those graph nodes weighted higher next time
  → If retrieval led to poor prediction →
    those graph nodes weighted lower

STEP 4: Results saved
  → outputs/results/backtest_metrics.csv
